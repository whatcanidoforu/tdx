# HJ10 底背离扫描（多周期）

在 **5 分钟 / 15 分钟 / 30 分钟 / 日线** 上，找 **HJ10 连续出现 ≥2 个低于阈值的低点，且后低点 HJ10 抬高、收盘价却创新低** 的股票，并记录每个低点和拐点的日期。

## ETF 支持

默认只扫 **A 股股票**，加 `--include-etf` 才纳入 ETF（沪市 51x/52x/56x/588、深市 159x）。

### 用法

```bat
:: 单只 ETF（无需 --include-etf，直接指定代码即可）
node hj-pivot-scanner.mjs --code=sh588200 --local

:: 全市场，股票 + ETF
node hj-pivot-scanner.mjs --local --include-etf

:: 调整 ETF 流动性门槛（默认 1000 万元）
node hj-pivot-scanner.mjs --local --include-etf --min-amount=5000
```

### 流动性过滤

ETF 里有大量流动性极差的品种，全量扫描会被垃圾标的淹没。因此 ETF 默认过滤：

> 近 **20 期**平均成交额 ≥ **1000 万元**（`--min-amount` 调门槛，`--lookback` 调统计窗口）

实测效果（15 分钟，2026-10-01~11-06）：

| 项 | 数量 |
|---|---|
| 沪市 ETF 文件 | 1669 只 |
| 流动性过滤后 | **324 只** |
| 过滤掉 | 1345 只 |

股票不受此过滤影响（避免误杀小盘股），除非显式用 `--min-amount`。

### ETF 价格精度（重要）

通达信给 ETF 的分钟线用了更高精度存储：**`.lc5` 里的价格是真实价的 1/10**。

| 标的 | `.day` 收盘 | `.lc5` 收盘 | 倍数 |
|---|---|---|---|
| sh588200（科创芯片ETF） | 8.38 | 0.838 | 10× |
| sh520980 | 7.47 | 0.747 | 10× |
| sh600000（股票） | 10.03 | 10.03 | 1× |

好消息：**HJ10、DIF 都是相对指标，1/10 完全不影响判定结果**。脚本在输出时自动乘以倍数还原真实价格（CSV 里会看到 10.200 而不是 1.0200）。

## 周期支持

用 `--period` 指定级别（默认 15）：

| 周期 | 参数 | 数据来源 | 默认建议阈值 |
|---|---|---|---|
| 5 分钟 | `--period=5` | `.lc5` 直接用（1 根） | 10 |
| **15 分钟（默认）** | `--period=15` | `.lc5` 每 3 根合成 | 10 |
| 30 分钟 | `--period=30` | `.lc5` 每 6 根合成 | 10 |
| 日线 | `--period=day` | 读 `.day` 文件 | **25** |

也可写 `--p=5`、`--period=5m`、`--period=日线`。

### 日线的阈值要单独调

HJ10 的 13 周期窗口在日线上跨 13 天，数值整体比分钟级别高。实测 200 只 × 120 日的数据：

| HJ10 分布 | 值 |
|---|---|
| 中位数 | 39.2 |
| 低于 25 | 25.7% |
| 低于 10 | 仅 1.9% |

所以**日线别用阈值 10**（几乎不会触发），建议 25，想要更严可以用 30/35。

### 实测各周期命中数（全市场，2026-10-01~11-06）

| 周期 | 参数 | 命中 | 耗时 |
|---|---|---|---|
| 5 分钟 | `--th=10 --md=1 --rc=15` | 387 只 | 14.2 秒 |
| 15 分钟 | `--th=10 --md=1 --rc=15` | 217 只 | 6.8 秒 |
| 30 分钟 | `--th=10 --md=1 --rc=15` | 79 只 | 5.7 秒 |
| 日线 | `--th=25 --md=1 --rc=40` | 1149 只 | 9.6 秒 |

周期越大，命中越少——符合「级别越大信号越稀缺」的直觉。

## 数据缺口自动补齐

本地 `.lc5` 可能缺少整个交易日（比如没做盘后下载，11-10 整天缺失）。
**HJ10 和 MACD 都基于 EMA 递推，缺口会被静默忽略**，把 11-09 当成 11-11 的前一根，算出错误指标。

脚本的处理方式是「**先补，补不上就告警**」：

1. 用主站返回的日期序列作为参照，检测本地缺失的交易日
2. 缺失日期自动从主站补齐（合并进本地历史）
3. 补不上时明确警告，不会静默算下去

运行时能看到：

```
  ✅ 自动补齐缺口：2673 只股票，缺失日期 20261110、20261111
     sh600000: 补 20261110,20261111（29 根）
```

想更严格，加 `--strict-gap`：检测到缺口且补不上时直接终止扫描。

### 一个已知的坑：指数不是股票

`898/899` 开头是**北证指数**，用的是不同的 K 线接口，价格与日期编码都和股票不一样，
解析出来是 `20130179` 这种垃圾日期。这类数据会污染缺口判断（误报几百个缺口日期）。

脚本做了两层防护：
- `security-type.js` 明确把 `898/899` 归为指数、不纳入股票池
- `gap-filler.js` 的 `sanitizeBars()` 过滤非法日期，防止解析异常的数据混入

## 大周期观察（日线背景）

信号本身是分钟级的，但大周期方向会影响效果。脚本会在每笔信号上附带日线状态：

| 列名 | 含义 |
|---|---|
| **日线连跌** | 买入日往前，日线 HJ10 已连续下跌几天 |
| **日HJ10降** | 买入日的日线 HJ10 是否低于前一交易日 |
| **日MACD降** | 买入日的日线 MACD 柱是否小于前一交易日 |

日线数据读 `vipdoc\{市场}\lday\*.day`，用完整历史计算（EMA 需要预热）。

### 作为筛选条件使用

默认这两个日线指标**只显示、不过滤**。想用它筛选，加开关：

这两个参数是**三态**：不传 = 不过滤，传 true/false = 按该条件筛选。

| 参数写法 | 含义 |
|---|---|
| （不传） | 不过滤，显示全部信号 |
| `--daily-hj10-down=true` | 只保留日线 HJ10 **下降**的 |
| `--daily-hj10-down=false` | 只保留日线 HJ10 **不下降**的 |
| `--daily-macd-down=true` | 只保留日线 MACD 柱 **缩小**的 |
| `--daily-macd-down=false` | 只保留日线 MACD 柱 **不缩小**的 |

可组合使用（同时满足）：

```bat
node hj-pivot-scanner.mjs --daily-hj10-down=true --daily-macd-down=true    # 双降
node hj-pivot-scanner.mjs --daily-hj10-down=false --daily-macd-down=false  # 双不降
node hj-pivot-scanner.mjs --daily-hj10-down=true --daily-macd-down=false   # HJ10降但MACD不缩
```

跑完会提示当前生效的条件：

```
  符合条件：11 只
  （日线条件：日线HJ10下降 + 日线MACD柱缩小；过滤掉 4 只）
```

取值也接受 `1`/`0`、大小写不敏感；不带 `=值` 时按 `true` 处理。

过滤后会提示：

```
  符合条件：13 只
  （日线条件过滤掉 5 只：需满足 日线HJ10下降）
```

实测（2026-11-11，18 个信号）：日线 HJ10 下降的有 13 只，日线 MACD 缩小的有 18 只。

### 分组统计

控制台会额外输出两张分组表，直接看大周期对胜率的影响：

```
  按日线 HJ10 连跌天数分组（看大周期影响）
  日线连跌    样本   T+1平均    T+1胜率   T+2平均    T+2胜率
  0天（日线走强或走平）    7     6.32%     85.7%     5.32%     71.4%
  1-2天                    27     5.10%     85.2%     3.77%     63.0%
  3-5天                   105     4.23%     95.2%     2.94%     73.3%
  6-10天                   70     4.69%     98.6%     4.04%     88.6%
  11天以上（日线持续走弱）  8     5.04%    100.0%     4.70%     87.5%

  按买入日的【日线】指标状态分组（买入日 vs 前一交易日）
  分组                     样本   T+1平均    T+1胜率   T+2平均    T+2胜率
  日线双降（HJ10+MACD）     205     4.49%     95.6%     3.41%     77.6%
  仅日线HJ10降                5     5.98%     80.0%     6.47%     80.0%
  仅日线MACD降                4     2.65%     75.0%     1.74%     50.0%
  日线双升（都不降）          3    11.22%    100.0%    10.10%    100.0%
```

### 实测发现的规律

**日线跌得越久，T+2 胜率反而越高**（63.0% → 88.6%）。这与"大周期走弱会拖累小周期"的直觉相反，可能的解释是：日线持续下跌代表超跌充分，此时分钟级底背离的反弹动能更强。

注意样本量：`0天` 和 `11天以上` 只有个位数样本，波动大；`3-5天`（105 个）和 `6-10天`（70 个）更可信。

另外「日线双降」占了 94%，是因为这批信号的买入日高度集中在 2026-10-09（150/217 只），那天日线整体在跌。换时间段数据会均衡很多。

## 多买点模式（默认）

**一只股票在日期范围内每出现一次买点，就输出一条记录。**

例：范围 2026-07-16 ~ 2026-11-11，某股票在这期间出现 5 次买点 → 输出 5 行。

```
sh688796 百奥赛图
  2026-08-27 11:00   买入价 119.740
  2026-09-07 13:30   买入价 118.040
  2026-09-28 14:00   买入价 126.500
  2026-10-23 10:45   买入价 80.500
  2026-11-11 11:15   买入价 74.940
```

表格按**买入时间倒序**排列，最近的买点在最前。

想只看每只股票最近一个买点，在代码里给 `detectDivergence` 传 `onlyLatest: true`。

### 实测数据（2026-07-16 ~ 2026-11-11，15 分钟）

| 指标 | 数值 |
|---|---|
| 总记录数 | 12,612 条 |
| 涉及股票 | 4,744 只 |
| 有多个买点的股票 | 3,516 只 |
| 单只最多买点 | 9 个 |

### 性能影响

**计算量没有增加**——背离链本来就全部构建好了，之前只是丢弃了除第一条以外的。

| 环节 | 耗时 |
|---|---|
| 扫描计算（5580 只） | **8.3 秒**（与单买点模式相同） |
| 后处理（补名称、日线上下文、CSV） | ~19 秒（记录数多 2.7 倍） |
| 总计（本地模式） | ~28 秒 |

不会卡。慢的部分是输出量变大，不是计算。

### 与日期范围的关系

- **指标计算和背离判定**始终用全量数据
- **日期范围**只筛选每个买点的买入日

所以单日扫描能抓到「昨天探底、今天形成拐点」的跨日买点，长范围扫描能列出期间所有买点。

实测一致性：长范围（7-16~11-11）里买入日在 11-11 的共 9 条，与单日扫描 11-11 的 9 只完全相同。

## 日期范围的作用

**指标计算与背离判定都用全量数据，日期范围只筛选「买入日」。**

买入日 = 背离链上**最后一个拐点**的日期和时间（看到它才能确认信号、下单）。

这样设计的好处：跨日的两次探底能被正确识别。例如：

```
603578 三星新材
  低点1  10-08 14:45  HJ10=10.37  收=13.78  → 拐点1  10-08 15:00
  低点2  10-09 11:30  HJ10=15.69  收=13.27  → 拐点2  10-09 13:15   ← 买入日
  
--start=2026-10-09 --end=2026-10-09  ✅ 命中（买入日在 10-09）
--start=2026-10-08 --end=2026-10-08  ❌ 不命中（买入日不在 10-08）
--start=2026-10-08 --end=2026-10-09  ✅ 命中
```

**所以单日扫描是有意义的**——能筛出「昨天探底、今天形成拐点」的跨日信号。

### 为什么不要求整条链都在范围内

底背离天然需要至少 2 个低点，而一天 16 根 15 分钟 K 线通常只够形成 1 个有效低点。
如果要求整条链都在范围内，单日扫描就永远是 0 只，失去意义。

### 不命中时会说明原因

```
有 2 条背离链，但买入日都不在 20261109~20261109 范围内
```

## 判定口径

### 核心概念

| 概念 | 定义 |
|---|---|
| **拐点** | HJ10 相对前一根**抬高**的那一根 |
| **低点** | 拐点前一根（HJ10 下行末端），且 HJ10 < 25 |
| **连续探底** | 两个低点之间没有被反弹打断 |

### 完整条件

两个相邻低点要连成一段，必须同时满足：

| # | 条件 | 说明 |
|---|---|---|
| 1 | 后低点 HJ10 > 前低点 HJ10 | 指标抬高 |
| 2 | 后低点收盘 < 前低点收盘 | 价格创新低 |
| 3 | **前低点 DIF < 后低点 DIF** | MACD 的 DIF 条件 |
| 4 | 低点左侧**连跌 ≥2 根** | 排除抖动 |
| 5 | 两低点间隔 ≥3 根 | 时间上不是紧挨着 |
| 6 | 两低点之间 HJ10 **没涨过 25** | 中间没反弹过 |

条件 1-2 是你的原始定义，3 是 DIF 条件，4-6 是抖动/反弹过滤。

### DIF 条件

DIF = EMA(CLOSE,12) − EMA(CLOSE,26)，取**低点那根 K 线**的 DIF 值。

用户原话「1的DIF < 3的DIF」，即前一个低点的 DIF 小于后一个低点的 DIF。

```
bj920138 的三级探底：
  低点1  09-29 14:15  DIF = -0.454
  低点2  09-30 10:45  DIF = -0.416   ← 比低点1高
  低点3  09-30 13:30  DIF = -0.380   ← 又比低点2高
```

> 注意：三星新材 603578 的例子中，低点1 的 DIF=−0.126、低点2 的 DIF=−0.209，
> `-0.126 < -0.209` **不成立**，所以加了这个条件后三星新材不再命中。
> 用 `--no-dif` 可关闭该条件。

### 为什么要加条件 3（左侧连跌根数）

拐点左侧连续下跌的根数，区分「真探底」和「抖动」：

```
603679 华体科技 11-04 09:45 的低点 HJ10=20.60
  往前看：11-03 15:00 = 21.51 → 20.60    只跌了 1 根  ← 抖动，忽略
  再往前：11-03 14:45 = 20.21

603679 华体科技 11-03 14:30 的低点 HJ10=17.84
  往前看：45.40 → 45.01 → 43.38 → ... → 17.84   连跌 11 根  ← 真探底
```

`--min-down=N` 可调，调大要求左侧跌得更久。

### 为什么要加条件 5（反弹上限）

中间 HJ10 涨上去了，说明**已经反弹过**，后面的低点不算「连续探底」：

```
603679 华体科技 11-02 10:00 低点 HJ10=14.08 → 拐点 10:15
  之后 HJ10 一路涨到 45.40（11-03 10:15）   ← 已经反弹了
  11-03 14:30 的 17.84 就不该和 14.08 连成一次探底
```

`--rebound-cap=25` 可调（默认与低点阈值一致）。

## 收益回测

每次扫描都会**同时生成两份文件**：

| 文件 | 内容 |
|---|---|
| `hj_<参数>.csv` | 选股结果（含买入价和 T+0/T+1/T+2 收益） |
| `hj_<参数>_统计.csv` | 收益统计（分段 + 逐笔） |

**文件名用指令参数拼**，例如：

```
hj_20260716-20261106_th10_md1_rc15_nodif_gp3.csv
 └─ 日期范围 ─┘      └阈值┘└连跌┘└反弹┘└DIF┘└间隔┘
```

### 买入价

**最后一个拐点的收盘价**——因为必须先看到拐点才能确认信号，那一刻才下得了单。

> 603578 三星新材：最后拐点是 10-09 13:15（HJ10=16.22），买入价 = 该根收盘 **13.38**（不是低点的 13.27）

### 卖出价

| 周期 | 含义 |
|---|---|
| **T+0** | 买入之后、**同一交易日剩余**的 15 分钟 K 线中的最高价 |
| **T+1** | 下一个交易日的最高价 |
| **T+2** | 再下一个交易日的最高价 |

收益 = `(卖出价 - 买入价) / 买入价 × 100%`

非交易日（如周末）自动跳过。

### 统计内容

1. **汇总**：T+0/T+1/T+2 各自的样本数、平均收益、最大、最小、胜率
2. **分段明细**：按 **1% 一段**统计笔数和占比
3. **逐笔明细**：每只股票的买入时间和三档收益

### 实测结果（最近 30 交易日，全市场）

| 周期 | 样本数 | 平均 | 最大 | 最小 | 胜率 |
|---|---|---|---|---|---|
| T+0 | 3682 | +2.63% | +32.87% | -0.32% | 95.2% |
| T+1 | 3720 | +3.44% | +36.77% | -6.92% | 86.3% |
| T+2 | 3715 | +3.05% | +48.64% | -13.95% | 77.6% |

> 注意：T+0 胜率 95% 偏高，因为「买入后当日最高价」这个口径下，价格几乎必然有一瞬间高于买入价。看 T+1/T+2 更有参考意义。

## 数据来源

脚本支持三种数据源，**默认 `--hybrid`**：

| 模式 | 数据来源 | 全市场耗时 | 适用场景 |
|---|---|---|---|
| **`--hybrid`（默认）** | 本地 `.lc5` 历史 + 主站补当天 | ~48 秒 | **盘中**，本地文件还没更新到当天时 |
| `--local` | 只读本地 `.lc5` | ~7 秒 | **盘后**，你已更新过本地文件 |
| `--live` | 全部从主站拉历史 | ~85 秒 | 本地文件缺失/损坏时 |

### 工作原理

按你的实际工作流设计：**每天收盘后更新本地 `.lc5`，盘中只补当天。**

1. 读本地 `vipdoc\{sh,sz,bj}\fzline\*.lc5` 全量历史（毫秒级）
2. 从行情主站**只拉每只最近 16 根** 15 分钟 K 线（`--tail=16` 可调）
3. 两者按「日期+时间」合并，实时数据覆盖本地同键记录

这样盘中既有完整历史（HJ10 的 EMA 需要预热），又能拿到当天最新的 K 线。

### 关键技术点

行情主站 K 线接口（`0x052d`）有个坑：

> **只能发 SetupCmd1，绝不能发 SetupCmd3。**
> 发完 setup3 后服务器会对所有 K 线请求返回错误码 `0x0320`。

**盘后**（已更新本地文件，最快）：

```bat
node hj-pivot-scanner.mjs --local
```

**盘中**（本地还没更新，自动补当天）：

```bat
node hj-pivot-scanner.mjs --start=2026-11-09 --end=2026-11-09
```

多看几个级别：

```bat
node hj-pivot-scanner.mjs --local --period=5
```

## 常用命令

```bat
# 扫描全部A股，默认最近30个交易日
node hj-pivot-scanner.mjs

# 指定时间范围
node hj-pivot-scanner.mjs --start=2026-10-01 --end=2026-11-06

# 只看单只股票，打印每个低点/拐点明细
node hj-pivot-scanner.mjs --code=sh603679 --start=2026-11-02 --end=2026-11-05 -v

# 要求更长的左侧下跌（过滤更多抖动）
node hj-pivot-scanner.mjs --min-down=3

# 要求更大的反弹才算"已反弹"（更宽松）
node hj-pivot-scanner.mjs --rebound-cap=30
```

## 参数

| 参数（长名 / 短名） | 默认 | 说明 |
|---|---|---|
| `--start` / `--end` | 最近30个交易日 | 时间范围（含边界） |
| `--code=sh603578` | — | 只扫单只股票 |
| `--period` / `--p` | 15 | K线周期：5 / 15 / 30 / day |
| `--threshold` / `--th` | 25 | 低点 HJ10 阈值 |
| `--min-down` / `--md` | 2 | 低点左侧最小连续下跌根数 |
| `--rebound-cap` / `--rc` | 25 | 两低点之间 HJ10 上限 |
| `--min-gap` / `--gp` | 3 | 相邻低点最小间隔（根） |
| `--min-pivots` / `--mp` | 2 | 最少低点数 |
| `--no-dif` | 启用 | 关闭 DIF 条件 |
| `--daily-hj10-down=true/false` | 不传=不过滤 | `=true` 只要下降的；`=false` 只要不下降的 |
| `--daily-macd-down=true/false` | 不传=不过滤 | `=true` 只要缩小的；`=false` 只要不缩小的 |
| `--min-rise` | 0 | 整链 HJ10 最小抬升量 |
| `--min-drop` | 0 | 整链最小跌幅百分比 |
| `--market=sh,sz,bj` | 全部 | 市场过滤 |
| `--include-st` | 否 | 包含 ST 股 |
| `--include-etf` | 否 | 包含 ETF |
| `--min-amount` | 1000 | ETF 流动性门槛（万元） |
| `--lookback` | 20 | 流动性统计窗口（根） |
| `--limit=N` | — | 只扫前 N 只（调试） |
| `-v` / `--verbose` | — | 打印低点/拐点明细 |

> **写错参数会直接报错并退出**，不会静默按默认值跑。例如 `--thresh=10` 会提示「无法识别的参数」。 
>
> 示例：`--start=2026-07-16 --end=2026-11-06 --th=10 --md=1 --rc=15 --no-dif`

日期支持 `2026-10-01`、`20261001`、`2026/10/01` 三种写法。
